## 2. Objective and real-world problem

Build a small command-line tool, `ask`, that sends one question to Claude, streams the answer, and prints a measurement line: input tokens, output tokens, stop reason, time to first token, total time and estimated cost.

**Real-world problem.** Teams that add an LLM feature often cannot answer "how much does one request cost, and why is it slow?". This tool makes those numbers visible from the first day. Every later part of the project reuses its client wrapper and its measurements.

## 3. Context in the project

This is the first ticket of the **Company AI Assistant**, a fictional internal assistant for a fictional company ("Northwind Tools"). Phase 1 creates the LLM client layer. Phase 2 puts it behind a FastAPI service and adds document search (RAG). Phase 3 adds tools and an agent loop. Later phases add evals, security, routing and cost control.

Decisions in this ticket that later tickets depend on: one module owns all calls to the model; every call is measured; secrets come only from the environment.

## 5. Functional and technical requirements

**Functional**

1. `python -m assistant.cli "your question"` streams the answer to the terminal as it arrives.
2. Before the call, the tool counts the input tokens with the token counting endpoint and prints the count.
3. After the call, it prints one measurement line: model, input tokens, output tokens, stop reason, TTFT in ms, total time in ms, estimated cost in USD.
4. Options: `--model` (default from the environment variable `ASSISTANT_MODEL`, else `claude-opus-5-5`), `--max-tokens` (default 1024), `--system` (optional system prompt).
5. When `stop_reason` is `max_tokens`, print a clear warning that the answer is incomplete.
6. When `stop_reason` is `refusal`, print a clear message and do not print partial text as an answer.

**Technical**

1. Use the official `anthropic` Python SDK. Do not call the HTTP API by hand. Do not use another vendor's tokenizer.
2. One module (`assistant/llm.py`) owns the client and the call. The CLI does not import `anthropic` directly.
3. The function in `llm.py` returns a typed result (a dataclass or a Pydantic model) with the text and the measurements.
4. Prices live in one table (`assistant/pricing.py`) with a comment that names the date you checked the pricing page.
5. Handle these errors with a clear message and an exit code that is not 0: authentication, permission, rate limit (show the retry-after value when present), bad request, connection error, timeout, other API status errors.
6. Use the SDK's built-in retries. Set `max_retries` explicitly so that the behavior is visible in the code.
7. Tests run without network access and without an API key.

## 6. Acceptance criteria

1. Given a valid key, when you run `ask "What is a token?"`, then text appears before the full answer is complete, and the measurement line shows non-zero input and output tokens and `stop_reason=end_turn`.
2. The printed input-token count from the count step equals `usage.input_tokens` of the response, or you can explain the difference in your handoff.
3. Given `--max-tokens 20` and a question that needs a long answer, the tool prints the incomplete-answer warning and `stop_reason=max_tokens`.
4. Given no `ANTHROPIC_API_KEY` (or an invalid one), the tool prints one clear error line, no stack trace, and exits with a code that is not 0.
5. The estimated cost equals input_tokens × input price + output_tokens × output price, and a unit test proves it.
6. `pytest` passes with the network off. The key value appears in no file in the repository and in no log line.
7. TTFT is smaller than the total time in every successful run.

## 9. Test cases and expected behavior

| Test | Input | Expected behavior |
| --- | --- | --- |
| `test_cost_is_input_plus_output` | 1,200 in, 300 out, Opus 5.5 prices | 0.0108 (compare floats with a tolerance) |
| `test_unknown_model_price_is_reported` | A model not in the table | A clear error or "unknown cost", never a silent 0 |
| `test_stream_collects_text_and_usage` | Fake stream with 3 text deltas | Result text is the joined deltas; tokens come from the final message |
| `test_ttft_not_greater_than_total` | Fake stream with a controlled clock | ttft_ms ≤ total_ms |
| `test_max_tokens_marks_incomplete` | Final message with stop_reason "max_tokens" | Result says incomplete; CLI prints the warning |
| `test_refusal_does_not_return_text_as_answer` | stop_reason "refusal" | Refusal result; no partial text shown as an answer |
| `test_rate_limit_error_message` | Fake client raises a rate-limit error | Clear message, retry-after shown when present, exit code not 0 |
| `test_auth_error_has_no_stack_trace` | Fake client raises an authentication error | One-line message; exit code not 0 |

Design hint: give `llm.py` a function that takes the client as an argument (dependency injection). Then a test can pass a fake client. Do not write the fake for the whole SDK; fake only the methods you call.

## 10. Security, reliability, performance and cost

- **Security:** the key comes only from the environment. `.env` is in `.gitignore`. Never log the request headers or the key. Print the environment variable name in error messages, never its value.
- **Reliability:** explicit timeout and `max_retries`. Distinguish "retry later" errors (429, 5xx, connection) from "fix the request" errors (400, 401, 403, 404).
- **Performance:** stream by default. Measure TTFT and total time with a monotonic clock (`time.perf_counter`).
- **Cost:** show the cost of every call. Use `claude-haiku-5-5` for repeated manual tests. Unit tests make no paid calls.
