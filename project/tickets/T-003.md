## 2. Objective and real-world problem

Build a small vector module and a command, `faq_search`, that ranks a fictional FAQ by cosine similarity to a query vector. All vectors are toy vectors in a JSON file. The ticket uses no API key, no network and no paid service.

**Real-world problem.** Before a team adds a vector database, it must trust the basic arithmetic and its edge cases: zero vectors, length mismatches, normalization and ranking order. Bugs here give no error. They only give bad answers. This ticket makes the arithmetic visible and tested, so that Phase 2 (RAG) can build on it.

## 5. Functional and technical requirements

**Functional**

1. `python -m assistant.faq_search money-back` loads the fixture, finds the query with the id `money-back`, and prints the documents ranked by cosine similarity, highest first, one line each: score (3 decimals), document id, title.
2. Option `--k N` prints only the top N results (default 3). When N is larger than the number of documents, it prints all documents.
3. Option `--vector "0.9,0.1,0.2"` uses that vector instead of a query id.
4. An unknown query id, a vector with the wrong length, or a zero vector gives one clear error line and an exit code that is not 0. No stack trace.

**Technical**

1. `assistant/vectors.py` has `dot`, `norm`, `normalize`, `cosine` and `top_k`, with type hints. Use pure Python (`math` only). Add no dependency.
2. `dot` and `cosine` raise `ValueError` for a length mismatch. `normalize` and `cosine` raise `ValueError` for a zero vector. The messages say what is wrong.
3. `top_k(query, docs, k)` takes a list of (id, vector) pairs and returns a list of (id, score) pairs, sorted by score, highest first. When two scores are equal, keep the input order.
4. `top_k` normalizes the query once. The fixture loader normalizes each document vector once at load time. The scores must equal the cosine values.
5. The fixture loader checks that every vector has the length that the fixture declares, and fails with a clear message when one does not.
6. The CLI does no arithmetic itself. It calls `vectors.py`.

## 6. Acceptance criteria

1. Given the fixture, when you run `python -m assistant.faq_search money-back`, then the output is, in this order: refund-policy 0.984, warranty-claims 0.933, delivery-times 0.421.
2. Given `--k 10`, the output lists all 4 documents, and the last one is vpn-setup 0.214.
3. Given `where-is-my-order`, the first line is delivery-times 0.993. Given `vpn-broken`, the first line is vpn-setup 0.989.
4. Given `--vector "0,0,0"`, the command prints one error line that names the zero vector, and the exit code is not 0.
5. Given `--vector "1,0"`, the command prints one error line that names the length mismatch (2 compared to 3), and the exit code is not 0.
6. `pytest` passes with the network off and with no `ANTHROPIC_API_KEY` in the environment.

## 10. Security, reliability, performance and cost

- **Security:** no network calls and no secrets. The ticket needs no environment variable. Do not add a key for an embedding provider to the repository.
- **Reliability:** validate input at the edges (fixture load, command arguments). Fail with a clear message. Never return a silent 0 for a zero vector.
- **Performance:** exact search costs about N × d multiplications per query. Normalize documents once at load time, not for each query. Write in the handoff at what size you would change to NumPy or a vector index.
- **Cost:** zero. No paid call, no new dependency.
