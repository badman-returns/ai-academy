## 2. Objective and real-world problem

Build the retrieval eval of the assistant. Write a labeled question set whose labels name document sections. Write a pure module with recall@k, precision@k, the reciprocal rank and nDCG. Write `scripts/retrieval_eval.py`, which sends each question through `retrieve_question` of T-018, prints one row for each k and caches the query vectors. **Real-world problem.** Teams tune RAG systems by reading a few answers. A change that helps one question breaks another, and nobody sees it until users complain. This ticket gives every later retrieval change a number, measured on the production retrieval path, with a gate that stops a regression.

## 5. Functional and technical requirements

**Functional**

1. `samples/rag_questions.jsonl` holds the 8 fictional questions of the lesson, one JSON object on each line: `id`, `question`, `relevant` (a map from a section id to the grade 1 or 2) and `must_pass`. Two questions have no answer in the documents and an empty `relevant`.
2. `python scripts/retrieval_eval.py` prints one summary line, one row for each k in 1, 3, 5 and 10 with recall, precision, MRR and nDCG at 3 decimals (the mean over the labeled questions), the skipped questions with their best score, and the misses at k = 3: each question with recall@3 below 1 and its missing sections. Options: `--embedder local|fake`, `--index DIR`, `--update-baseline`.
3. When `samples/retrieval_baseline.json` exists, the script also prints the baseline line, the candidate line, the fixed and broken ids, and `verdict: PASS` or `verdict: FAIL` with one line for each reason. The exit code is 0 for a pass and 1 for a fail.
4. `--update-baseline` writes the run only after a pass, or when no baseline exists. After a fail, it writes nothing and says so.
5. The script stops with an error that names the question and the section when a label names a section that is not in the index.

**Technical**

1. A new pure module `assistant/retrieval_metrics.py` holds `relevant`, `gain`, `recall_at_k`, `precision_at_k`, `reciprocal_rank`, `dcg` and `ndcg_at_k` with the rules of the lesson. It has no I/O and imports no model or web library.
2. The rules: a result is relevant when one of its sections has a grade of 1 or more; its gain is the highest grade of its sections; recall counts labeled sections and raises `ValueError` when there is none; precision divides by k; the reciprocal rank is 0 with no relevant result in the top k; DCG is the sum of gain / log2(rank + 1); the ideal list sorts the gains of all chunks in the index.
3. The script gets the ranked list from `retrieve_question(question, index, embedder, k=10, min_score=0)` and maps each result to the `sections` of its chunk.
4. `CachedEmbedder(inner, path)` wraps an embedder with the same interface. Its `embed_query` reads and writes `.cache/query_vectors.json`, with the key `short_hash(model + "\n" + text)`. The script saves the cache at the end and prints `embed_calls`, the number of calls to the inner embedder. Add `.cache/` to `.gitignore`.
5. `compare_retrieval(baseline, run)` in `assistant/gate.py` returns a `GateResult` of T-016. It fails when `questions_hash` differs, when recall@3 (rounded to 3 decimals) is lower than the baseline, or when a must-pass question is not a hit. A question is a hit when every section with grade 2 is in the top 3. `fixed` and `broken` list the questions whose hit changed.
6. The baseline file has the keys `questions_hash` (the `short_hash` of the question file), `embedder`, `chunker`, `chunks`, `k` (3), `rows`, `must_pass` and `cases`. Each case has `id`, `hit`, `first_rank` and `recall` (at k = 3). A change of the embedder or the chunker is a normal candidate, not a reason to fail.
7. The tests make no network call. They build the T-017 fixture index with the fake embedder under `tmp_path`, at 20, 10 and 40 words.

9. Given a label with the section refund-policy#returns, the script stops and names q01 and that section.
10. Given `--update-baseline` and a failed gate, the baseline file does not change.
11. With the real embedder, milestone 4 records the rows, the skipped questions with their best scores, the misses and the first verdict in the handoff.

## 10. Security, reliability, performance and cost

- **Cost:** no Claude call. The cache makes a second run free of embedding calls.
- **Speed:** the fixture eval runs in less than one second, so it can run in every test run.
- **Validity:** the eval uses the retrieval function of the service, and the labels survive a change of the chunks.
- **Reproducibility:** the baseline names the question file hash, the embedder and the chunker.
- **Testability:** the metrics are pure functions with hand-checked cases.
