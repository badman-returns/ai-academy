## 5. Functional and technical requirements

**Functional**

1. `next_token_loss(target_probs) -> float` returns the mean of −ln p. `perplexity(mean_loss) -> float` returns exp of it.
2. `sft_loss(target_probs, loss_mask) -> float` returns the sum of −ln p over the tokens with mask 1, divided by the number of those tokens.
3. `reward_model_loss(r_chosen, r_rejected) -> float` returns −ln σ(r_chosen − r_rejected). `reward_model_probability` returns σ of the difference.
4. `preference_policy(ref_probs, rewards, beta) -> list[float]` returns π_ref · exp(r / β) / Z. `kl_divergence(p, q) -> float` returns KL(p ‖ q) in nats.
5. `dpo_loss(policy_chosen_logp, policy_rejected_logp, ref_chosen_logp, ref_rejected_logp, beta=0.1) -> float` returns −ln σ(margin) as in the lesson.
6. `sft_steps(logits, demo_index, steps, learning_rate) -> list[float]` runs gradient descent on −ln softmax(logits)[demo_index], as the interactive does.
7. `python -m assistant.training` loads `data/training_toy.json` and prints one row for each stage at 3 decimals: the base model, SFT after 10 steps, preference tuning with β = 1, and the flawed reward model with β = 0.25. Each row has the 4 probabilities, the KL from the SFT model, the reward model score and the human rating.
8. `assistant/datasets.py` has the dataclasses `SftExample` (a list of messages with roles) and `PreferencePair` (prompt, chosen, rejected, meta), with `validate()`, and `load_jsonl` and `append_jsonl` functions.
9. `python scripts/collect_preferences.py --model claude-haiku-5-5 --seed 1` reads `data/prompts.txt`. For each prompt, it gets two replies with two different system prompts, shows them as 1 and 2 in a random order, reads 1, 2 or s (skip), and appends a `PreferencePair` to `data/preferences.jsonl`.

**Technical**

1. Pure functions in `training.py`: no global state, no printing inside the functions, no change to the input lists.
2. Numerical safety: `preference_policy` works in log space and subtracts the largest value before exp. The losses compute −ln σ(x) with `math.log1p`, so a margin of ±1000 gives a finite result.
3. Input checks raise `ValueError` with a clear message: lists of different lengths, a mask with no 1, a probability outside (0, 1], and β ≤ 0.
4. `SftExample.validate()` checks that the roles alternate between user and assistant, that the last message is from the assistant, and that no content is empty. `PreferencePair.validate()` checks that chosen and rejected are not empty and not equal.
5. The collector reuses the T-001 client and prints the T-001 cost line for each call. Its meta field stores the model id, both system prompts, the display order and the token usage. It never stores or prints the API key.
6. Type hints on every public function. A docstring on `dpo_loss` that states the formula.
7. The tests make no network call and need no API key. The collector test uses a fake client and a fake input function.

## 6. Acceptance criteria

1. Given [0.2, 0.5, 0.8], `next_token_loss` returns 0.842 and `perplexity` of that loss returns 2.321 (tolerance 0.001).
2. Given the probabilities [0.9, 0.95, 0.99, 0.9, 0.5, 0.25, 0.8, 0.9] and the mask [0, 0, 0, 0, 1, 1, 1, 1], `sft_loss` returns 0.602. A mask with no 1 raises `ValueError`.
3. `reward_model_loss(1.5, 0.5)` returns 0.313, and `reward_model_loss(0.5, 1.5)` returns 1.313.
4. `preference_policy([0.5, 0.5], [1, 0], 1.0)` returns [0.731, 0.269], and with β = 0.5 it returns [0.881, 0.119]. With β = 0.001 it returns [1.0, 0.0] and raises no error.
5. `dpo_loss(-10, -15, -12, -14, beta=0.1)` returns 0.554. When the policy and the reference values are equal, it returns 0.693. A margin of −1000 gives a finite loss.
6. Given the fixture, 10 SFT steps give the probabilities [0.099, 0.811, 0.060, 0.031]. With the flawed reward model and β = 0.25, the "padded" reply gets 0.995, and the human rating falls from 1.423 (SFT) to 0.507. The lesson's interactive shows the same numbers at 2 or 3 decimals.
7. For every display order, the collector saves the reply that it showed as 1 as `chosen` when the input is 1. The input s saves nothing.
8. `pytest` passes with the network off. `python -m assistant.training` prints the numbers of criterion 6.

## 10. Security, reliability, performance and cost

- **Correctness first:** readable loops are fine. Speed does not matter for a few values.

- **No new dependencies:** standard library and the `anthropic` package of T-001 only.
