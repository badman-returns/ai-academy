## 2. Objective and real-world problem

Write a grounding module, `assistant/grounding.py`, and the first FastAPI endpoint of the assistant, `POST /ask` in `assistant/api.py`. The endpoint retrieves FAQ documents with your T-003 vector functions, returns "I don't know" without a model call when no document passes the minimum score, sends a grounded prompt to Claude with the T-001 client, and checks each citation in the answer. Prove each behavior with tests that use a fake model and are named after the properties they check.

**Real-world problem.** An internal assistant that invents a refund rule or a policy causes real cost, and users stop trusting it. Teams that ship assistants make each answer traceable to a source and make "I don't know" a normal, tested result. This ticket builds that pattern in a small form that you can test offline.

## 5. Functional and technical requirements

**Functional**

1. `load_corpus(path) -> Corpus` loads `data/grounding_faq.json` and checks that every vector has the length of `dimensions`.
2. `retrieve(corpus, vector, k=2, min_score=0.5) -> list[Source]` uses `top_k` from T-003 and keeps only the sources with a score of at least `min_score`. A `Source` has `id`, `title`, `text` and `score`.
3. `build_prompt(question, sources) -> tuple[str, str]` returns the system prompt and the user message. The system prompt states three rules: answer only from the sources, cite each source id in square brackets, say "I don't know" when the sources do not contain the answer. The user message has each source in a `source` tag with an `id` attribute, then the question.
4. `parse_citations(answer) -> list[str]` returns the ids in square brackets, in order, without duplicates.
5. `grounded_answer(question, vector, corpus, ask, k=2, min_score=0.5) -> GroundedAnswer` returns one of four statuses:
`no_sources` (nothing retrieved, no model call), `abstained` (the model said "I don't know"), `answered` (at least one citation, and every cited id was retrieved) or `unsupported` (no citation, or an id that was not retrieved).
6. `POST /ask` takes `{"question": str, "vector": list[float], "k": int = 2, "min_score": float = 0.5}` and returns `{"status", "answer", "citations", "sources": [{"id", "score"}]}` with the scores at 3 decimals. `GET /health` returns `{"status": "ok"}`.
7. `python -m assistant.grounding refund-window` loads the fixture, finds the query with that id, prints the retrieved sources with their scores, and prints the prompt. With `--live`, it also sends the prompt to Claude and prints the status and the answer.

**Technical**

1. `grounding.py` does not import `anthropic` or `fastapi`. It gets the model as a function `ask(system: str, user: str) -> str`.
2. `api.py` builds `ask` from the T-001 client in `assistant/llm.py` through a FastAPI dependency. Tests replace this dependency with a fake (`app.dependency_overrides`).
3. Pydantic models for the request and the response. A vector of the wrong length gives HTTP 422 with a message that names both lengths. `k` must be 1 to 10 and `min_score` must be 0 to 1.
4. The corpus loads once at start-up, not on each request.
5. Log one line for each request: status, retrieved ids with scores, cited ids, and the input and output tokens when the model was called. Never log the API key.
6. Type hints on every public function. A docstring on `grounded_answer` that names the four statuses.
7. The tests make no network call and need no API key.

## 6. Acceptance criteria

1. Given the fixture and the `refund-window` vector, `retrieve` with k = 2 and min_score = 0.5 returns refund-policy 0.984 and warranty-claims 0.933, in this order.
2. Given the `warranty-length` vector, `retrieve` with k = 1 returns only refund-policy (0.995). With k = 2 it also returns warranty-claims (0.983).
3. Given the `vacation-days` vector, `grounded_answer` returns the status `no_sources` and the answer "I don't know", and the fake model is not called.
4. Given one source, the user message from `build_prompt` has the `source` tag with `id="refund-policy"` before the line that starts with `Question:`, and the system prompt contains "I don't know".
5. Given the answer "Within 45 days [refund-policy]. Express takes 1 day [delivery-times]." and the retrieved ids refund-policy and warranty-claims, the status is `unsupported`, and the citations are ["refund-policy", "delivery-times"].
6. `POST /ask` with the `refund-window` vector and a fake model that returns "You can return an unused tool within 45 days [refund-policy]." gives HTTP 200, the status `answered` and the citations ["refund-policy"].
7. `POST /ask` with a vector of length 3 gives HTTP 422, and the message names 3 and 4.
8. `pytest` passes with the network off. `uvicorn assistant.api:app` starts, and `GET /health` returns `{"status": "ok"}`.

## 10. Security, reliability, performance and cost

- **Reliability:** "I don't know" is a normal result with a status, not an error. The service never returns an unsupported answer without its status.
- **Cost:** the `no_sources` path makes no model call. The log line shows the token counts of each call.
- **Security:** the key comes only from `ANTHROPIC_API_KEY`. Never log or return it. The document text goes into the prompt inside tags, and the system prompt says to answer only from the sources. Topic 7 covers prompt injection in documents.
- **Testability:** the unit tests and the API tests need no network and no key. The model is a function that the tests replace.
