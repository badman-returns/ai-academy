## 2. Objective and real-world problem

Add a token meter to the T-001 project. A new command, `python -m assistant.count`, measures a text for one or more models: characters, UTF-8 bytes, input tokens, tokens for each 100 characters and the estimated input cost. The T-001 command, `python -m assistant.cli`, gets an optional input token limit. It checks the limit before it sends the paid request.

**Real-world problem.** Teams often forecast cost with a "characters per token" rule. The forecast is wrong for other languages, code and IDs, and the team learns this from the bill. This ticket replaces the guess with a measurement, and stops oversized requests before they cost money.

## 3. Context in the project

This is the second ticket of the **Company AI Assistant** for the fictional company "Northwind Tools". It builds on T-001. T-001 decided that one module (`assistant/llm.py`) owns all calls to the model, that every call is measured, and that secrets come only from the environment. T-002 keeps all three decisions.

Later tickets use the token meter: the FastAPI service (Phase 2) needs a request size limit, and cost control (later phases) needs real token counts for each model.

## 5. Functional and technical requirements

**Functional**

1. `python -m assistant.count --file samples/en.txt` prints one row for each model: model, characters, UTF-8 bytes, input tokens, tokens for each 100 characters, estimated input cost in USD.
2. The text comes from `--file` or from a positional argument. `--models` takes a comma-separated list of model ids. The default is the value of `ASSISTANT_MODEL`, else `claude-opus-5-5`.
3. The count command only counts. It never sends a request that generates text.
4. `assistant.cli` gets the option `--max-input-tokens`. The default comes from the environment variable `ASSISTANT_MAX_INPUT_TOKENS`. When neither is set, there is no limit.
5. When a limit is set and the counted input is above it, `assistant.cli` prints the count and the limit in one clear line, does not send the request, and exits with a code that is not 0.
6. A `samples/` folder holds at least five short texts that you write: English, the same text in a non-Latin script that you know (for example Hindi or Bengali), source code, a list of numbers or IDs, and text with emoji. No customer data and no secrets.

**Technical**

1. Token counts come only from `client.messages.count_tokens`, through one function in `llm.py` (for example `count_input_tokens(client, model, messages, system=None)`). If T-001 already has this function, reuse it. Do not write a second one.
2. `count.py` and `cli.py` do not import `anthropic`. Do not use another vendor's tokenizer.
3. `assistant/tokens.py` holds pure functions with no network: `text_stats(text)` returns characters (code points) and UTF-8 bytes, and `tokens_per_100_chars(tokens, chars)` returns a float.
4. Count with the same model id as the request. For each model, send one count request. Send the requests one after another.
5. Count errors use the T-001 error mapping: the same messages and the same exit codes.
6. When a limit is set and the count fails, `assistant.cli` stops with the error. It never sends a request that it could not check.
7. The cost column uses `pricing.py` and its header says "input only".
8. Tests run without network access and without an API key.

## 6. Acceptance criteria

1. Given `samples/en.txt` and two models, when you run the count command, then it prints two rows with input tokens above 0, and the characters and bytes match `len(text)` and `len(text.encode("utf-8"))`.
2. Given the text `नमस्ते`, when `text_stats` runs, then it returns 6 characters and 18 bytes. Given `café`, it returns 4 and 5. Given `👍`, it returns 1 and 4.
3. Given a limit lower than the counted input, when you run `assistant.cli`, then it prints the count and the limit, exits with a code that is not 0, and the fake client in the test records zero stream calls.
4. Given a limit equal to the counted input, when you run `assistant.cli`, then the request is sent.
5. Given an empty text, when you run the count command, then it prints a clear error and does not divide by zero.
6. The handoff contains your prediction table (written before the first run) and your measured table for all samples on two models.
7. `pytest` passes with the network off. The key value appears in no file in the repository and in no log line.

## 10. Security, reliability, performance and cost

- **Security:** the key comes only from the environment, as in T-001. The samples contain no customer data and no secrets. Do not log the full prompt text; log its counts.
- **Reliability:** the limit check never lets an unchecked request through. A count error stops the request with a clear message.
- **Performance:** the count is one more network round trip before each request. Measure it with `time.perf_counter` and show it, so that you can decide if it is worth it.
- **Cost:** the count command never generates text. Use `claude-haiku-5-5` for repeated manual tests of `assistant.cli`. Unit tests make no network calls.
